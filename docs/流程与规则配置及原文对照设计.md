## 2. 流程线（「流程与规则」页）

### 2.1 流程定义（每个员工一份，版本化）

```
流程(employee, version)
 ├─ 节点[]：id、名称、类型（取单 / 取数 / 下载 / 解析 / 归集 / 抽取 / 外部查询 / 校验 / 报告）、
 │          说明、数据来源（合同系统表单、台账 86 / 78、天眼查、四份制度、资料中心缓存…）、产出（事实名）
 └─ 规则集：规则[]（见第 3 节），每条声明 执行节点 + 依赖节点 / 事实
```

现有代码中的节点与规则依赖关系整理成这份定义（初始数据从代码与需求文档整理，人工核对）；运行时仍由现有流水线执行，定义用于展示、配置与一致性校验（定义中的节点必须与流水线一致，测试保证）。

### 2.2 页面

- 左：员工与流程版本切换。
- 中：流程线（节点卡片横向排列，标注数据来源）；每个节点下挂「在此执行的规则」，并用连线 / 标签表示「依赖此节点的规则」；三会的 5 个审查节点直接画成节点。
- 右：选中节点或规则的详情（只读查看；有编辑权限时可编辑规则，见第 3 节）。
- 与方案对照：每个员工一张「需求方案步骤 ↔ 实际节点」对照表，标注一致 / 拆分 / 差异：

| 场景 | 需求方案 | 实际节点 | 差异说明 |
|---|---|---|---|
| 采购 | 拉取待办 / 归集材料 / 附件预处理 / 规则校验 / 生成报告 | 取单 → 下载附件 → 解析材料 → 归集材料 → 抽取事实 → 规则校验 → 生成报告 | 「拉取待办」因待办只读改为台账 / 已办采集 + 人工发起；「附件预处理」拆为下载、解析、抽取 |
| 合同 | 进入审核 / 启动 / 材料准备 / 并行规则校验 / 汇总报告 | 取单 → 读取台账 → 下载附件 → 解析材料 → 归集材料 → 抽取事实 → 外部查询 → 规则校验 → 生成报告 | 多出「读取台账」「外部查询」两个取数节点（方案隐含在材料准备） |
| 三会 | 进入审核页 / 材料解析 / 业务核验 / 结果展示 / 人工处理 / 重新审查；审查节点 01–05 | 取单 → 下载附件 → 解析材料 → 归集材料 → 抽取要素 → 制度检索 → 审查（N01–N05）→ 生成报告 | 审查节点与方案一一对应；「人工处理」在系统外 |
| 报销 | 以需求说明书为准（八类单据） | 取单 → 下载附件 → 解析材料 → 归集材料 → 抽取要素 → 规则校验 → 生成报告 | 通财云取数未打通，取单走本地事项 |

- 运行数据（可选叠加）：节点平均耗时 / 失败次数（`node_run`），规则近 N 次命中分布。
- 入口：左侧导航「流程与规则」；对话开场「查看与追溯」加按钮；资料中心页加链接。

## 3. 规则可配置

### 3.1 绑定方式：规则集绑流程，规则挂执行节点并声明依赖

- 不只绑节点：一条规则常需要多个节点的数据（如 R02 要合同正文、投标文件、技术协议）；集中在校验节点并发执行，才能保证每条都有明确状态、整单完成才出报告（需求要求）。
- 不只绑流程：看不出依赖哪个节点的数据；取数节点异常（如天眼查不可用）时无法说明影响哪些规则。
- 三会例外：审查节点即规则。

### 3.2 规则配置项（第一期：配置已有规则，不新建）

| 类别 | 内容 |
|---|---|
| 基础 | 启用 / 停用（停用必须写原因，报告中记「未执行」并显示原因）；显示名称；结论档位（采购「一定不通过 / 拿不准」；合同 / 三会 / 报销沿用现有口径） |
| 参数 | 规则声明的参数表（类型、单位、取值范围、默认值），如违约金比例上限、签订时限天数、陪餐人数、人均标准、敏感词、央企名录、上年度发票截止月份 |
| 适用条件 | 规则声明的条件开关（如 R27 仅监理 / 项目管理业务、R29 / R30 仅含技术协议时执行） |
| 提示文案 | 异常提示模板（支持 `{金额}`、`{差值}` 等规则提供的变量），不改判定逻辑 |
| 说明 | 依据、业务口径备注、对接人 |

判定逻辑仍在代码中；每条规则在代码里声明「可配置参数表 + 文案变量 + 适用条件」，配置页只能改这些声明过的项，并按类型校验。

### 3.3 版本、发布与留痕

- 草稿 → 发布：发布生成新的规则版本号（如 `contract-2026.11.10-r2`）；报告记录版本号，执行档案存当时的规则配置快照。
- 每次修改留痕（谁、何时、改了什么、原因）；可查看版本差异、回退到历史版本。
- **发布后不自动重审**：已有报告标注「按旧版规则生成」，资料中心与任务清单提供「按新版规则批量重审」。
- 存储：数据库表（规则配置、版本、变更记录），现有 YAML 作为初始数据导入，并支持导入 / 导出。
- 权限：部署时随门户统一认证按岗位授权（查看 / 编辑 / 发布分开）；开发期先不做登录，所有修改记录操作人填写的姓名。

## 4. 合同原文对照（报告中「对照原文」→ 全屏对照页）

### 4.1 页面

- 右：问题清单（发现问题 / 人工复核 / 待补充），可按规则或按文件分组；每项显示规则编号、结论、说明。
- 左：源文件查看器（文件页签 + 分页浏览）；点击或悬停右侧某项 → 左侧切到对应文件、翻到对应页并高亮原文位置；一条规则有多条证据（如合同 vs 投标文件）时可逐条切换，或左侧分屏并列对照（需求 3.1「原文 / 目标文本并列对照」）。
- 证据无法精确定位时显示整页并标注「未精确定位」，不伪造位置（需求「不得伪造页码」）。

### 4.2 定位能力

| 文件类型 | 精度 | 做法 |
|---|---|---|
| 文字层 PDF（合同正文多为此类） | 句级 | 资料中心按页渲染图片，文字层检索原文片段得到坐标 |
| 扫描件 | OCR 行 / 版面块 | OCR 坐标 |
| Word / Excel | 段落 | 左侧显示解析后的正文（保留段落、表格），高亮对应段落；不转分页图 |
| 模型引用原文与实际有出入 | 页级 | 沿用原文引用校验，对不上时只给页 |

- 后端：按文件 / 页返回页面图片与高亮坐标（一次计算，按报告缓存）；Word / Excel 返回段落文本与命中段落位置。
- 左侧显示原件（审核人可见的业务材料），不打码；执行档案仍按打码规则。
- 组件做成通用：本期合同；采购、三会、报销后续复用。

## 7. 实施结果（2026-11-10）

| 部分 | 实现 |

与方案的差异（如实说明）：
- 「提示文案模板（带变量）」改为「核实建议」：判定结论的说明仍由规则生成，配置项在问题 / 复核时追加一条核实建议，避免逐条改造规则文案。
- 「适用条件」第一期未做成配置项：各规则的适用条件仍在判定逻辑中（流程页的依赖与说明可见）；需要业务可改的条件，后续逐条在代码中声明为参数后开放。

验收：
- 自动化 257 项通过（新增 `test_flows.py`、`test_locate.py`，接口冒烟覆盖草稿校验 → 发布 → 版本号 → 按新版批量重审 → 停用规则记「未执行」 → 导出 / 导入 / 回退 → 原文对照接口）；测试默认使用隔离的规则配置库，正式环境发布的配置不影响回放。
- 真实环境（张建浩账号，`tools/e2e_live_check.py`）72/72：三个场景无回退；合同 1671817 发布测试配置后新报告版本 `+c1`、R07 核实建议进入报告、档案含配置快照；原文对照 9 项需关注、27 条证据中 23 条精确定位（文字层 / OCR / 段落），其余为审批表单、天眼查等非文件证据或仅定位到页；恢复默认并重审后真实环境回到代码默认规则（版本记录中保留这两次验收发布，留痕可查）。
