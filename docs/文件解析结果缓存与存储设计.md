# 文件解析结果的缓存、存储与查询设计

> 版本：2026-11-06 初稿　｜　适用：四个数字员工共用　｜　依据：`M0-合同系统取数摸底.md`

## 1. 目标

1. **同一内容只处理一次**：同一份文件无论出现在哪笔单据、被哪个数字员工使用，下载后的 OCR、解析、大模型抽取都只做一次，之后直接复用。
2. **可追溯**：任何一条结论都能追到「哪份文件、哪一页、哪段原文、由哪个版本的解析器产生、什么时候产生」。
3. **防篡改**：缓存结果带完整性签名，读取时校验；被改动过的结果视为未命中并告警。
4. **来源无关**：解析由我们自己做，或客户做完推送过来，都进同一套存储，按同一规则命中。
5. **独立维护**：自建 PostgreSQL + 对象存储，不依赖 autoagent_flow 的任何组件。

## 2. 三个签名

| 名称 | 计算方式 | 作用 |
|---|---|---|
| 内容签名 `content_sig` | `SHA-256(文件原始字节)` | 文件身份。与文件名、上传人、所在流程无关 |
| 处理键 `proc_key` | `SHA-256(content_sig + 处理器名 + 处理器版本 + 参数摘要)` | 缓存键。处理器升级或参数变化即为新键，旧结果保留 |
| 完整性签名 `integrity` | `HMAC-SHA256(服务端密钥, content_sig + proc_key + 结果字节的 SHA-256)` | 防篡改。读取时重算比对 |

说明：
- 参数摘要包括 OCR 引擎与模型、DPI、语言、是否版面分析等，保证「同样的输入 + 同样的做法」才算同一结果。
- 服务端密钥只存在服务配置中，不入库、不入代码。
- 若客户推送的结果自带签名，入库时先验客户签名，再加我们的完整性签名；两者都保存。

## 3. 处理层级与缓存

| 层级 | 处理器示例 | 输入 | 输出 | 缓存键 |
|---|---|---|---|---|
| L0 原件 | — | 下载字节 | 原件 | `content_sig` |
| L1 解析 | `pdf_text@1`、`ocr_rapid@1`、`docx@1`、`doc_legacy@1`、`archive@1`、`customer_push:<名称>@<版本>` | 原件 | 统一文档 JSON（第 5 节） | `proc_key` |
| L2 抽取 | `extract:采购公告@3` 等 | L1 结果 | 结构化字段 + 原文引用 | `SHA-256(L1 结果签名 + 抽取模式版本 + 提示词版本 + 模型)` |
| L3 外部查询 | `tyc:关联关系@1` 等 | 公司名/信用代码 | 查询结果 | 查询键 + 有效期（默认 7 天，可配） |
| L4 整单报告 | `procurement@规则版本` | 全部材料签名 + 表单字段摘要 | 报告 | `SHA-256(排序后的材料签名 + 表单摘要 + 规则版本)` |

- L0–L2 **永不过期**：内容不变，结果就不变。
- L3 有有效期：工商、司法信息会变。
- L4 用于「材料和规则都没变时，秒出上次报告」；任何一份附件或表单字段变化都会导致不命中。

压缩包：解压后每个子文件都是独立的 L0/L1；父文件的 L1 结果只记录子文件签名列表与层级关系。

## 4. 存储布局

### 4.1 对象存储（MinIO，一期可用本地目录，路径规则相同）

```
blobs/<sig前2位>/<content_sig>                     原件，只写一次，不可改
parsed/<content_sig>/<proc_key>/document.json      L1 统一文档
parsed/<content_sig>/<proc_key>/pages/<n>.png      渲染页图（OCR 与证据高亮用，可选）
extract/<proc_key>.json                            L2 抽取结果
reports/<task_id>.json                             报告快照
```

### 4.2 PostgreSQL 表

```sql
-- L0：一份内容一行
CREATE TABLE file_blob (
  content_sig   char(64) PRIMARY KEY,
  size_bytes    bigint      NOT NULL,
  mime          text,
  ext           text,
  magic_hex     text,                      -- 文件头，用于识别真实格式
  storage_uri   text        NOT NULL,
  first_seen_at timestamptz NOT NULL DEFAULT now()
);

-- 文件在客户系统中的每一次出现（同一内容可出现多次）
CREATE TABLE file_occurrence (
  id            bigserial PRIMARY KEY,
  content_sig   char(64) NOT NULL REFERENCES file_blob,
  source_system text     NOT NULL,         -- contract / odoc / caiwuyun / customer_push
  request_id    text,                      -- 客户系统单据号
  workflow_id   text,
  field_key     text,                      -- field14072
  field_label   text,                      -- 附件 / 采购文件 …
  file_id       text, image_file_id text, version_id text,
  filename      text,
  upload_time   timestamptz,
  secret_level  text,
  fetched_at    timestamptz NOT NULL DEFAULT now(),
  task_id       uuid,
  UNIQUE (source_system, request_id, field_key, image_file_id, content_sig)
);
CREATE INDEX ON file_occurrence (source_system, request_id);
CREATE INDEX ON file_occurrence (content_sig);

-- 文档属性（规则 10：作者同一人）
CREATE TABLE file_meta (
  content_sig      char(64) PRIMARY KEY REFERENCES file_blob,
  author text, last_modified_by text, created_at_doc timestamptz, modified_at_doc timestamptz,
  producer text, title text, page_count int
);

-- L1：解析结果索引
CREATE TABLE parse_result (
  proc_key      char(64) PRIMARY KEY,
  content_sig   char(64) NOT NULL REFERENCES file_blob,
  processor     text NOT NULL,             -- ocr_rapid
  processor_ver text NOT NULL,
  params_digest text NOT NULL,
  origin        text NOT NULL,             -- self / customer_push
  status        text NOT NULL,             -- ok / partial / failed
  page_count    int, char_count int, ocr_pages int,
  quality       real,                      -- 平均 OCR 置信度等
  result_uri    text,
  result_sha256 char(64),
  integrity     char(64) NOT NULL,         -- HMAC
  ext_signature text,                      -- 客户推送时自带的签名
  error         text,
  duration_ms   int,
  created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON parse_result (content_sig);

-- 页级文本（证据定位 + 全文检索）
CREATE TABLE parse_page (
  proc_key  char(64) REFERENCES parse_result ON DELETE CASCADE,
  page_no   int,
  method    text,                          -- text / ocr
  ocr_conf  real,
  text      text,
  PRIMARY KEY (proc_key, page_no)
);
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX ON parse_page USING gin (text gin_trgm_ops);

-- L2：抽取结果
CREATE TABLE extract_result (
  extract_key    char(64) PRIMARY KEY,
  proc_key       char(64) NOT NULL REFERENCES parse_result,
  schema_name    text NOT NULL,            -- 采购公告
  schema_ver     text NOT NULL,
  prompt_ver     text NOT NULL,
  model          text NOT NULL,
  result         jsonb NOT NULL,           -- 字段值 + 原文引用（页码、片段）
  integrity      char(64) NOT NULL,
  tokens_in int, tokens_out int, duration_ms int,
  created_at     timestamptz NOT NULL DEFAULT now()
);

-- L3：外部查询
CREATE TABLE external_cache (
  query_key   char(64) PRIMARY KEY,
  provider    text NOT NULL,               -- tyc
  query_type  text NOT NULL,               -- 关联关系 / 主要人员 / 失信
  subject     text NOT NULL,               -- 公司名或信用代码
  result      jsonb NOT NULL,
  integrity   char(64) NOT NULL,
  fetched_at  timestamptz NOT NULL DEFAULT now(),
  expires_at  timestamptz NOT NULL
);

-- 每次缓存访问（回溯与命中率统计）
CREATE TABLE cache_access (
  id        bigserial PRIMARY KEY,
  task_id   uuid,
  layer     text,                          -- L1 / L2 / L3 / L4
  cache_key char(64),
  hit       boolean,
  verified  boolean,                       -- 完整性校验是否通过
  ms        int,
  at        timestamptz NOT NULL DEFAULT now()
);
```

任务、规则结果、证据、审计日志等表见《数字员工项目计划》第 8 节；证据表通过 `content_sig + proc_key + page_no` 指回这里。

## 5. 统一文档 JSON（L1 输出）

不论来自文字层、OCR 还是客户推送，都转换成同一结构，下游规则只认这一种：

```json
{
  "content_sig": "547c26e3…",
  "processor": "ocr_rapid", "processor_ver": "1", "origin": "self",
  "meta": {"author": null, "producer": "QuarkPDFCore", "page_count": 2},
  "pages": [
    {"no": 1, "method": "ocr", "ocr_conf": 0.94, "width": 1240, "height": 1754,
     "blocks": [
       {"type": "para",  "text": "采购需求审批表", "bbox": [120, 80, 860, 130], "conf": 0.98},
       {"type": "table", "bbox": […], "cells": [[{"text": "预算金额", "row": 0, "col": 0}, …]]}
     ]}
  ],
  "children": [],
  "warnings": ["第2页存在印章遮挡，置信度 0.71"]
}
```

`bbox` 用于页面上的证据高亮；`warnings` 中的低质量页会在报告里提示人工核对。

## 6. 处理流程

```
下载原件 → 计算 content_sig
  ├─ file_blob 已存在？否 → 写对象存储 + file_blob；读文档属性写 file_meta
  ├─ 写 file_occurrence（记录这次出现）
  └─ 选择处理器（按真实文件头，不按扩展名）→ 计算 proc_key
        ├─ parse_result 命中且完整性校验通过 → 直接返回（界面显示「复用解析结果」）
        ├─ 命中但校验失败 → 记告警，按未命中处理
        └─ 未命中 → 对 proc_key 加 PostgreSQL 咨询锁
                     → 再查一次（防并发重复）→ 解析 → 写对象存储 → 写 parse_result / parse_page
                     → 释放锁
```

- **并发**：两笔任务同时遇到同一份文件，只有一个真正做 OCR，另一个等锁后直接命中。
- **PDF 选择**：先读文字层；每页文字少于阈值才对该页 OCR，混合 PDF 按页处理。
- **失败**：解析失败也写一条 `status=failed` 的记录（含错误），下游规则判为「未能识别」并注明文件；同一 `proc_key` 的失败结果可配置重试次数。
- **客户推送**：推送接口接收「原件签名 + 解析结果」，`processor = customer_push:<名称>`，走同一张表。原件不在我们手里时，`file_blob.storage_uri` 为空，只保存签名。

## 7. 查询

### 7.1 服务接口

| 接口 | 用途 |
|---|---|
| `GET /files/{content_sig}` | 文件信息、文档属性、所有出现过的单据 |
| `GET /files/{content_sig}/parse?processor=&ver=` | 解析结果（默认取最新版本中状态为 ok 的） |
| `GET /files/{content_sig}/pages/{n}` | 页文本与页图（证据定位） |
| `GET /requests/{system}/{request_id}/files` | 某笔单据的全部附件及解析状态 |
| `GET /search?q=&system=&from=&to=` | 全文检索（`pg_trgm`），返回文件、页码、片段 |
| `GET /cache/stats?from=&to=` | 各层命中率、节省的 OCR/模型耗时 |
| `POST /ingest/parsed` | 客户推送解析结果 |

### 7.2 典型查询

```sql
-- 某笔单据的附件及解析状态
SELECT o.field_label, o.filename, b.size_bytes, p.processor, p.status, p.page_count, p.quality
FROM file_occurrence o
JOIN file_blob b USING (content_sig)
LEFT JOIN LATERAL (
  SELECT * FROM parse_result r WHERE r.content_sig = o.content_sig AND r.status = 'ok'
  ORDER BY r.created_at DESC LIMIT 1) p ON true
WHERE o.source_system = 'contract' AND o.request_id = '853872';

-- 规则 10：不同供应商的响应文件作者相同
SELECT m.author, array_agg(DISTINCT o.filename)
FROM file_occurrence o JOIN file_meta m USING (content_sig)
WHERE o.request_id = :rid AND o.field_label LIKE '%响应%' AND coalesce(m.author, '') <> ''
GROUP BY m.author HAVING count(DISTINCT o.content_sig) > 1;

-- 同一文件出现在哪些单据
SELECT source_system, request_id, field_label, filename, fetched_at
FROM file_occurrence WHERE content_sig = :sig ORDER BY fetched_at;
```

## 8. 版本、保留与安全

- **版本**：处理器、抽取模式、提示词、规则都有版本号；升级后产生新键，旧结果与旧报告保留，历史报告始终能看到当时依据的结果。
- **保留**：按需求「暂时永久留存」；后续可按 `last_access` 做冷数据归档。
- **密级**：`secret_level` 随出现记录保存；接口按调用人权限过滤（权限模型随工作台一起做）。
- **日志**：日志只记签名、文件名与耗时，不记录全文。
- **备份**：PostgreSQL 每日备份；对象存储内容按签名寻址，可增量备份并逐个校验。

| 项 | 一期 | 后续 |
