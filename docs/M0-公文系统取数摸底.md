# M0 公文系统（三会「内部请示」）取数摸底记录

> 日期：2026-11-09　｜　账号：测试账号（刘辉），在调试 Chrome 中人工登录门户，程序只借用会话
> 结论：**三会场景的取数已打通**。全部为接口回放（纯 HTTP），不渲染页面；OA 会话失效时自动经统一认证续期。
> 实现：`digital-employees/core/sources/docflow.py`；测试：`tests/test_docflow.py`（合成数据）。

## 1. 已验证的结论

| 项 | 结论 |
|---|---|
| 系统 | 致远 Seeyon（`https://oa-xc.gt.cn/seeyon`），模板「通用设计内部请示」（templateId `1263920733801892953`） |
| 单点登录 | 带门户统一认证 cookie 访问 `GET /seeyon/tyssj.do?method=access&targetUrl=<OA 内地址>`，经 `login/sso?from=gtsso` → `main.do?method=login&ticket=…` 跳转后写入 OA 会话（JSESSIONID）。**纯 HTTP 即可完成，不需要浏览器** |
| 单号定位 | 门户工作台列表 `API_CODE_FINDPERSONALWORKS`（app=4）按标题关键字搜索；内部请示的 `mark` 字段为空，内请号只出现在 `subject` 中，须用 `subject` 参数搜 |
| 列表类型 | `pending` 待办、`pendingRead` 待阅、`donePending` 已办、`doneRead` 已阅、`doneSent` 我的发起、`pendingSent` 草稿。**取数只查 doneSent / donePending / doneRead**，不打开他人待办 |
| 去重 | 同一份请示在「我的发起」「已办」中 affairId 不同，`objectId`（summaryId）相同，按 summaryId 去重 |
| 表单 | `content.do` 返回 HTML，每个字段是 `<span fieldVal='{name, displayName, inputType, value}'>`；字段前的「xxx：」单元格是可见标签（如「审批/上会依据」，displayName 为「审批上会依据」） |
| 会议类型 | 不是一个字段，而是 5 个复选框（董事会 / 党委会 / 总经理办公会 / 专题会 / 不上会），`value` 1 表示勾选；适配器按前置标签「会议类型」合成一个字段 |
| 单选 | 如「是否“三重一大”事项」，选中项为 `<input checked="true">`，其后文字为选项名 |
| 附件 | 表单附件字段的 `attsdata` 与 `deal-base-info.attachmentInfo.attachments` 两处都有，按 `fileUrl` 去重；`type=0` 为文件，其余为关联文档（不下载，记入 `extra.linked_docs`） |
| 附件下载 | `GET /seeyon/fileDownload.do?method=download&fileId=<fileUrl>&createDate=<yyyy-MM-dd>&v=<签名>&filename=…` → 302 到 `method=doDownload` → 文件。**缺 `v` 返回 404**；`v` 随会话变化，不能当版本号（缓存键用 fileUrl + 上传时间） |
| 性能 | 每份：定位 + 详情 + 表单约 2 s，附件 0.3 s |

## 5. 公司数据查询 → 内部请示查询（2026-11-10，账号张建浩）

张建浩的「我的发起 / 已办 / 已阅」中没有可审的内部请示，改从 OA 空间「公司数据查询」页签的「内部请示查询」
取数（工具 `tools/m0_docflow_query.py`，`--open <行 id>` 在查询页调用页面自身的行点击函数打开一条详情并记录请求）。

| 项 | 结论 |
|---|---|
| 入口 | `tyssj.do` 单点登录到空间页 `portal/spaceController.do?method=showThemSpace&spaceId=5055268928752140374` → 点「公司数据查询」页签 → 「内部请示查询」，打开 `form/queryResult.do?method=queryExc&type=query&queryId=-4037857976162825094` |
| 查询接口 | `POST /seeyon/ajax.do?method=ajaxAction&managerName=formQueryResultManager&nn=getQueryResult`，表单体 `managerMethod=getQueryResult&arguments=[{page,size},{queryInfo}]`；`queryInfo.userCondition` 的条件运算符用 `include`（包含），`like` / `=` 返回 500 |
| 结果 | 全公司 1084 条（已结束 873、未结束 152、终止 59）；列：`field0001` 内请号、`field0002` 标题、`field0012` 申请人、`field0009` 申请部门、`field0013` 申请时间、`field0003` 是否三重一大、`field0004` 事项类型、`finishedflag` 流程状态、`field0007` 会议类型，另有 `summaryId` 与 `id`（表单记录） |
| 打开详情 | 行点击打开 `govdoc.do?method=summary&summaryId=<summaryId>&openFrom=formQuery&operationId=-6155648955446964314.-3563027052804682398&formId=-5612251084050314838`；`deal-base-info` 与 `content.do` 同样支持 `openFrom=formQuery`（content.do 的 affairId 取 `summaryInfo.affair.affairId`，是发起人的已发事项） |
| 会话失效 | 该接口不跳登录页，而是返回 JSON 字符串 `"__LOGOUT"`，适配器按会话失效处理（单点登录后重试一次） |
| 单会话 | **OA 同一账号只允许一处在线**：任何地方（资料中心、工作台截图用的无头浏览器、调试 Chrome、其他脚本）经 `tyssj.do` 单点登录后，之前的 OA 会话即失效——接口返回 401 `{"code":"1007","message":"您的帐号在另一地点登录，您被迫下线"}`，附件下载返回一个移动端网页而不是文件；附件下载签名 `v` 与会话绑定，换会话后旧签名返回 404 |
| 应对 | 适配器遇到「被迫下线」/ 下载返回网页 / 旧签名 404 时重新单点登录，并重新取单换新签名后重试一次；公文平台页面截图推迟到本单附件下载完成之后再开始，截图中页面提示被迫下线时重新打开一次 |
| 页面发出的写类请求 | 打开详情时页面会发 `govdocLockManager.activeLockTime`（编辑锁续期）、`lockSeeyon/checkHadViewAuth`、`rest/track/log`（浏览埋点），平台页面截图时一律拦截；接口取数不发这些请求 |

**只读约定**：只打开流程状态为「已结束」的请示；未结束的可能是他人待办（如 371 号是张建浩的待办），定位后直接拦截，
不读详情（`allow_pending_detail: true` 之前）。人事议题仍不采集。

**实测**：通设请字[2026]342号（智能体开发平台及数字员工建设项目采购结果，总经理办公会，依据权责手册运营管理部第46项）
表单 18 个字段、6 份附件（请示 .doc、采购需求审批表、采购结果审批表、评审报告、采购公告、供应商报价资料）全部读取下载。

**请示正文 .doc**：内部请示正文多为 WPS 另存的 Word 97 `.doc`。原先的近似提取（整个文件按 UTF-16 解码）会混入
文档属性里的旧标题（342 号与 307 号的属性标题都是沿用模板留下的「关于公司CAD软件正版化的请示」）和嵌入对象乱码，
导致 04 请示正文误报「标题不一致」、表格数值丢失。现按 [MS-DOC] 分段表（FIB → Clx → PlcPcd）只读正文流，
表格按行列还原、域代码只留显示结果；读不出分段表时才回退近似提取并标注。

## 6. 通财云（报销）现状

门户工作台 app=1 的「我的发起」中有本人提交的 14 张金蝶云苍穹单据（差旅 / 对公 / 对私 / 资产采购），
详情地址形如 `https://fc.gt.cn/ierp/?formId=gt_er_tripreimbursebill&pkId=…`。
**从外网访问 `fc.gt.cn` 会被重定向到 `/ierp-prompt`：「该系统暂不支持直接从外网访问，请先连接 VPN 客户端」**，
需要在本机连接 VPN 后才能继续摸底。
