## 2. 接口清单

| 用途 | 方法与路径 | 关键参数 | 说明 |
|---|---|---|---|
| 待办列表 | `POST /api/workflow/reqlist/splitPageKey` | `viewScope=doing` | 返回 `sessionkey`，即下一步的 `dataKey` |
| 已办列表 | 同上 | `viewScope=done` | |
| 列表分类树 | `POST /api/workflow/reqlist/doingBaseInfo` / `doneBaseInfo` | | `treedata` 中 `wf_100` 等即流程 ID |
| 列表分页 | `POST /api/ec/dev/table/datas` | `dataKey, current, pageSize` | 行内含 `requestid / workflowid / requestname / currentnodeid` |

| 表单 | `POST /api/workflow/reqform/loadForm` | `requestid` | 字段定义在 `tableInfo.main.fieldinfomap`，值在 `maindata.field<ID>` |
| 日志前置 | `POST /api/workflow/reqform/getRequestLogBaseInfo` | 取自 `loadForm.params` | 返回 `viewLogIds`、`creatorNodeId` |
| 审批日志 | `POST /api/workflow/reqform/getRequestLogList` | 上两步参数合并 | `loglist[].log_operatedate/log_operatetime/log_nodename/displayname/displaydepname/operationname` |
| 附件下载 | `GET /weaver/weaver.file.FileDownload?fileid=…&download=1&requestid=…&authStr=…&authSignatureStr=…` | 取自字段的 `filedatas[].loadlink` | 链接带单据级授权签名，**每次取数都要从表单重新拿**，不能缓存链接 |

字段取值规则：
- 下拉（htmltype=5）：`value` 是选项值，名称在 `fieldinfomap[ID].selectattr.selectitemlist`。
- 浏览（htmltype=3）：`value` 是 ID，名称在 `maindata.field<ID>.specialobj[].name`（含 HTML，需去标签）。
- 附件（htmltype=6）：`maindata.field<ID>.specialobj.filedatas[]`，含 `filename / fileid / imagefileid / versionId / uploaddate / loadlink / secretLevel`。

## 5. 对后续设计有影响的发现

1. **扫描件是常态**：已看到的 PDF 全部是整页图片、无文字层（扫描 App 生成），OCR 是必经环节。
2. **Word 有文档属性**：`author / last_modified_by / created` 可读，规则 10（投标文件作者同一人）可行；但 PDF 扫描件没有有效作者信息。
3. **格式要兼容老式 .doc / .xls**。
4. **同一文件会在多个流程中出现**（如采购需求审批表同时挂在 wf=790 与 wf=100），按内容签名去重能省掉重复 OCR。
5. **附件有密级字段** `secretLevel`，存储时一并记录。
6. **副作用**：页面打开表单时会调用 `updateReqInfo`、`InsertSystemPageViewLog`（记录查看）。接口回放只调 `loadForm`，不调这两个；对待办单据是否仍会记为已读，需拿一笔测试单验证。

对规则设计的影响：
1. **响应文件是采购代理统一扫描的**（三家 PDF 的 producer 均为同一台复印机 `ApeosPort-V C7785`），PDF 属性不能用于规则 10，否则必然误报。
2. 规则 10 可用的电子原件是报名信息里的**信息登记表 docx**，但其中两家的 author、last_modified_by、created 完全相同（疑为采购方下发的模板），需先与采购文件/模板的属性比对、排除模板继承，再判断雷同。
3. 单笔需 OCR 约 **140 页**（响应文件 124 + 评审 16），OCR 吞吐与缓存是性能关键。
4. rar 解压需服务器装 `bsdtar`/`unar`，并按 GBK 修正文件名。

**1358481（新版表单，在审）**：直接采购（电子签章更新），4 份附件（固定资产购买申请、采购需求审批表、报价单、直接采购说明），停在「1.经办人」，未见公告/结果附件。

**对正式运行的含义**：历史样例与评测集从台账取（量大、已有最终结论）；**在审单据**只在审核岗（徐冉、陈曦）的待办中出现，正式账号需具备该节点的待办或流程监控权限。

规则对应：
- 规则 13（关联关系）：股东、对外投资、实际控制人交叉比对；疑似关系可作为线索。
- 规则 14（主要人员重叠）：主要人员 + 股东 + 最终受益人姓名交叉。
- 规则 15（资信）：失信被执行人、被执行人、破产重整。
- 疑似关系里的「相同邮箱/电话」也可辅助规则 11。

注意事项：
- 这是**公用账号**，同一账号多处登录可能互相挤下线，正式运行前需与使用方约定登录时段或单独开子账号。
- 天眼查有频率与反爬限制：按公司缓存（L3，默认 7 天）、串行限速，失败记「未能识别」，不当作通过。
